# 部品室 — 部品管理PWA

Googleスプレッドシートを保存先に、部品の初期登録・情報変更・使用・購入・棚卸を記録するアプリです。

台帳：[部品管理台帳](https://docs.google.com/spreadsheets/d/1ApO3COCM41WX2jgb4oKjV2d-3gUfYGLZ1kQOwfEadJM/edit)

## 現在の状態

- アプリとGoogle Apps Scriptの接続用コードを実装済み。

## ローカルで開く

Node.js 22.13以上を使用します。

```sh
npm run install:ci
npm run dev -- --hostname 127.0.0.1
```

ブラウザーで http://127.0.0.1:5173 を開きます。接続前でも「お試しモード」で部品を登録できます。

## Googleとの接続（初回のみ）

ブラウザーで http://127.0.0.1:5173/setup.html を開くと、コードのコピー機能付きガイドが表示されます。

1. 作成済みの台帳を開き、「拡張機能 → Apps Script」を選択します。
2. `public/download/Code.gs` の内容で初期コードを置き換えて保存します。
3. 関数 `setup` を実行します。Googleの権限確認をご自身で行い、台帳に表示された接続キーを控えます。
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選択します。実行ユーザーは「自分」、アクセスできるユーザーは「全員」に設定します。
5. 発行された `/exec` のURLと接続キーを、アプリの「接続設定」に入力します。

公開されるAPIの入口は接続キーで保護されます。スプレッドシート本体の共有権限は変更しません。接続キーを知る人はアプリで台帳を読み書きできます。キーは部員だけに共有してください。Google Workspaceのポリシーで「全員」を選べない場合、この公開方式は利用できません。

接続キーはブラウザーのローカルストレージに保存されます。共有端末で使い終えたら「接続設定 → 接続を解除」で端末内のキーと在庫キャッシュを消去してください。結果未確認の記録がある場合は、先に再送して確定させます。

キーを失効させる場合は、Apps Scriptのプロジェクト設定のスクリプトプロパティ `ACCESS_TOKEN` を削除し、`setup` を再実行して新しいキーを発行します。各端末で設定を更新します。

## スマホ用に公開する

アプリはVinext / Cloudflare Workers向けのビルドを使用します。公開時は `/api/inventory` も動くサーバー環境が必要です。静的ファイルだけのホスティングではGoogle連携が動きません。

```sh
npm run build
```

Sitesの環境ではSitesプラグインの公開手順を使用します。この作業中に公開用プラグインファイルが利用できなくなったため、公開URLは発行していません。

HTTPS公開後、iPhoneはSafariの共有メニューから「ホーム画面に追加」、AndroidはChromeのメニューからインストールできます。manifest、192/512pxアイコン、maskableアイコン、Service Worker、オフライン閲覧画面を実装しています。スマホの実機インストールは公開後の確認が必要です。

## 管理する項目

部品名、用途、型番、価格、調達先、数量、単位、当面必要な在庫、発注予定、確認日、備考、URLを管理します。照合用に部品IDを追加しています。

- 数量は小数点以下6桁まで。例えば1袋100個なら、10個の使用を `0.1` 袋として記録します。
- 価格は管理単位あたりの金額です。希望小売価格か調達額かは備考に残してください。
- 「補充が必要」は現在庫が必要在庫を下回った部品です。
- 部品名を押すと詳細と編集画面が開きます。
- 在庫を修正する場合は「棚卸で数量を修正」から実数と理由を記録します。
- 記録者名は自己申告です。本人認証による監査ログではありません。

## 台帳と履歴の関係

「増減履歴」が原本で、「部品台帳」は履歴から再作成する一覧です。**部品情報・数量はアプリから変更してください。** スプレッドシートの一覧を直接編集した値は、次の同期でアプリの値に戻ります。既存の手入力台帳を取り込む機能は含めていません。

履歴の「操作内容」列には復旧用の部品情報と操作内容を保存します。履歴行やこの列を削除・編集しないでください。並べ替えは可能です。登録後の単位は履歴の整合性のため変更できません。単位を変える場合は別の部品として登録します。

同時操作はApps Scriptのロックで直列化します。在庫不足はサーバー側でも拒否します。通信エラー時は同一の記録IDで再送し、二重計上を防ぎます。履歴の保存後に一覧の更新が失敗した場合、再送または再取得で一覧を復旧します。

オフラインは保存済み在庫の閲覧のみです。未送信の在庫変更を自動でキューに入れる機能はありません。Google Apps Scriptの利用上限内で動く部室規模のアプリです。履歴を全件取得するため、大量の記録が蓄積する運用ではページ分割などの追加対応が必要です。

## 開発と検証

```sh
npm test
npm run typecheck
npm run build
```

`lib/inventory.ts` が在庫計算の共通実装です。`scripts/build-apps-script.mjs` はそれと `apps-script/backend.js` をまとめて配布用の `Code.gs` を生成します。開発起動・ビルド・テストの前に自動生成します。バックエンドを変更したら、Google側のコードを更新し、デプロイのバージョンも更新してください。

テストでは小数計算、在庫不足、再送、複数利用者の競合、古い情報での上書き拒否、棚卸、単位の整合性、式注入対策、履歴保存後の投影失敗と復旧を確認します。Apps ScriptのローカルテストはGoogleサービスを模擬しています。Googleへの実接続テストは初回設定後に必要です。

Google公式資料：[Web Apps](https://developers.google.com/apps-script/guides/web)、[LockService](https://developers.google.com/apps-script/reference/lock/lock-service)
